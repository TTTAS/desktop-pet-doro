# 素材工廠：GIF 轉檔與對齊 Doro 規格（計畫與目標）

狀態：2026-10-14 已實作第 1–3 階段，分支 `claude/relaxed-sagan-wgumxk`（`5dbfad8`、`3f354fd` 及第 3 階段提交），尚未開 PR。
第 3 階段依外部審查（見文末）修正：角色大小與動畫活動範圍分開計算。
本文件同時給其他 AI／審查者看：最後一節列出希望被挑戰的決策。程式碼與測試優先於本文。

## 問題

1. 素材工廠原本只吃 MP4、只輸出 WebP／APNG，不能處理網路上抓的 GIF。
2. Doro 以動畫的**原始像素大小**顯示（`SpriteController` 把 `movie.frameRect()` 設成 sprite size），
   所以大小不一的 GIF 匯入後角色忽大忽小。
3. 就算把畫布統一成同一尺寸，各 GIF 的**透明留白**不同，角色本體仍然大小不一、腳的高度也不一致。

## 目標

- 任何來源（ComfyUI 影片、網路 GIF、日後 Live2D 錄影）匯入後，看起來和內建 Doro **一樣大、站在同一條線上**。
- 不需要使用者手動裁切或縮放；預覽時就能看出大小是否合適。
- Doro 執行時只播放 GIF／WebP／APNG，不新增渲染路徑（延續 2026-08-15 移除 Live2D 渲染的決策，見 `CHANGELOG_session_2026-08-15.md`）。

非目標：動作語意分類、AI 自動判斷姿勢、Live2D／Spine 執行時渲染、雲端處理。

## Doro 規格（實測自 `doro_app/res` 內建 13 支動畫）

| 項目 | 實測 | 採用預設 |
| --- | --- | --- |
| 畫布 | 全部 200×200（`SPRITE_DEFAULT_WIDTH/HEIGHT = 200`） | 200 |
| 角色本體高 | 待機／點擊／拖曳 146–149；站姿 `stand.gif` 167（其他站姿 169–173） | 167，可調 |
| 腳底 y | 184–187，多數 186（離底 13–14） | 186 |

座標語意：「腳底 y=186」是**邊界**，和 Pillow `getbbox` 的右／下界一樣不含該列；最後一列實心像素是 y=185。內建素材也是用同一方式量的，兩邊一致。
| 角色寬 | 約 170–190 | 上限 190 |

## 已完成

### 第 1 階段：GIF 進出（`5dbfad8`）

- `extract_frames`：`.gif/.webp/.apng/.png` 改由 Pillow 讀，逐格合成、保留原透明及逐格時間（`ExtractedVideo.durations`）；
  0–19 ms 的影格比照瀏覽器當 100 ms。
- 去背模式新增 `none`（保留原透明）；只選動圖時自動切到此模式。
- 輸出新增 GIF：255 色＋透明索引，alpha < 128 視為透明，`disposal=2` 避免殘影。
- 尺寸模式：維持原尺寸／縮小長邊（只縮不放）／統一 N×N 畫布（可放大、底部置中）。

### 第 2 階段：對齊 Doro 規格（`3f354fd`，第 3 階段已修正其縮放方式）

- `DoroSpec(canvas=200, body_height=150, foot_y=186, max_body_width=190)`，建構時驗證不合理組合。
- `body_bounds`：整支動畫所有影格 alpha ≥ 32 的聯集範圍（忽略 AI 去背淡雜點）。
- `fit_to_doro`：用聯集框裁切 → 縮放至 `min(身高/h, 寬上限/w)`（可放大）→ 水平置中、底緣對 `foot_y`。
  整支共用同一縮放，角色在動畫內移動時不抖動。
- 視窗：新尺寸選項＋「身高」欄位；預覽疊 35% 不透明的內建站姿 Doro（`res/state/stand.gif`）與紅色腳底虛線。
  不去背時預覽用整支動畫範圍；去背模式下以目前這格估算並在狀態列註明。
- CLI：`--doro`、`--body-height`；與 `--size/--canvas` 互斥。
- 驗證：完整離屏測試 1224 passed、4 skipped；3 個 rembg 測試因環境未安裝 AI 套件失敗（與本變更無關）。Ruff、repo_map --check 通過。
  以使用者提供的素材（490×498、角色約 240×307）實測：輸出角色 117×150，腳在 y=186。

### 第 3 階段：分開角色大小與活動範圍（依外部審查）

審查實測第 2 階段的 `fit_to_doro`：同一個 60×120 角色，原地不動時高 150，加一格跳起只剩 78，左右滑動只剩 63——
用聯集範圍決定縮放，會讓不同動作忽大忽小。修正後：

- `plan_doro_layout` 回傳整支共用的 `DoroLayout`（裁切框、縮放、貼上位置、被裁切格數）：
  - **縮放**：每格角色高／寬的中位數對齊身高與寬度上限，跳躍、位移、單一異常格都不影響大小。
  - **位置**：聯集下緣（最低的腳）對到 `foot_y`，活動範圍水平置中；跳起的格保留離地高度。
  - **超界**：不縮小角色，裁掉超出畫布的部分並回報 `clipped_frames`；視窗與 CLI 都會提示哪支幾格。
    橫越整個畫面的素材可能有格數整個被裁掉，這是刻意取捨（Doro 的走路由視窗移動完成，素材應原地播放）。
- **預覽／整支動畫／單格 PNG 共用同一套擺放**：`doro_layout_for_frame` 在不去背且不內縮時用整支動畫計算，
  結果與整支輸出逐像素相同；去背模式只能以該格估算，預覽會明示「整支輸出時會以全部影格重算」。
- **預設身高改為 167**，與參考 `stand.gif` 相同；參考 Doro 以腳底中點為基準跟著所選身高縮放，比對才準。
- **GIF 量化**：透明像素藏的 RGB（常為黑）先填成畫面已有的顏色，不再佔用 255 色中的一格。
- 驗證：完整離屏測試 1236 passed、4 skipped；3 個 rembg 測試因環境未安裝 AI 套件失敗。
  使用者素材在身高 167 時輸出 131×167，與參考 Doro 同高、腳在 y=186。

## 已知限制

- **身高是單一數字**：坐姿、趴姿若用同一身高會失真，目前靠使用者手動調低；中位數只能處理「多數格同一姿勢」的動畫，站→坐這類混合姿勢仍會偏。
- **腳底 = 最底部像素**：影子、特效、地面物件會讓腳底判斷錯；需靠陪伴設定既有的「腳底校正」微調。
- **畫風差異**：不同角色頭身比不同，身高相同不代表看起來一樣大（例如頭大身小的角色會顯得更大）。
- **大幅動作超出畫布**：固定 200×200、保持角色大小、完整保留任意大幅動作三者無法同時滿足；目前選擇裁切並提示。
- **GIF 一位元透明**：半透明柔邊以 50% 取捨，邊緣較硬；在意畫質應輸出 WebP／APNG。
- **預覽估算**：AI／顏色去背時預覽只用目前這格的範圍；大幅動作時可能和整支輸出差很多（已在狀態列明示）。

## 下一步（尚未實作，按優先序）

1. **依姿勢的身高預設**：下拉選「站／待機／坐／趴」對應 167／150／120／90，取代裸數字；坐、趴的數值是待驗證的經驗值。
2. **腳底偵測強化**：排除小型孤立雜點、從接地影格估計地面線；保留素材級手動錨點，不確定時讓使用者確認。
3. **命名規格**：例如 `Doro v1`，由使用者按「從參考素材建立規格」更新並記下來源，不自動跟著 stand 素材變動。
4. **GIF 全動畫共用調色盤**、像素風素材改用最近鄰縮放。
5. **以頭部大小對齊**（研究，排最後）：頭寬也受髮型、轉頭影響，需可靠的頭部偵測。
6. **匯入時自動提示**：從圖庫直接匯入外來 GIF 時，偵測尺寸／腳底偏離規格並建議先經素材工廠。
7. **Live2D 當動畫來源**：用 Cubism Editor 免費版或 Inochi2D 錄影 → 素材工廠 → 匯入，不恢復執行時渲染。
   封存模型 `res/Dororong_Live2D_Model_/` 作者標示為 0x4682B4，散布前需確認授權。
8. **AI 生成來源**：維持 ComfyUI 影片 → 素材工廠的流程；固定同一張 Doro 參考圖提升一致性。

## 希望審查者（其他 AI）挑戰的問題

1. 以「全身高」為縮放基準是否合理？有沒有更穩的跨素材基準（頭寬、面積、骨架關鍵點）？
2. 用「整支動畫聯集範圍」裁切，相較逐格或取中位數範圍，對跳躍／大幅移動的動作是否最好？
3. 腳底偵測只看最底部 alpha 像素，是否值得改成「最底部且連通面積夠大」或用 AI 姿勢估計？
4. 167／186／190 這組規格應寫死成常數，還是從使用者目前的 stand 素材動態量測？（審查建議：版本化的命名規格，見下一步 3）
5. GIF 輸出的透明處理（255 色量化、alpha 128 門檻、不抖色）有沒有更好的做法，例如加描邊減少鋸齒？
6. 預覽疊參考 Doro 的方式（35% 不透明、放在素材後面）是否足夠直觀？
7. 有沒有免費／開源工具能比這套流程更省事地把網路動圖整理成一致的桌寵素材？
