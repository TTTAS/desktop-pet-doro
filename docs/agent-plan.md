# Doro 任務助理計畫

2026-10-13，延續 `codex/comprehensive-web-automation`，來源分支不變動。
使用者補充希望效仿 [OpenClaw](https://github.com/openclaw/openclaw)：不只網站操作，
而是可接收目標、選工具、保存進度與記憶的個人助理。採用其任務、工具及持久狀態的概念，
沿用 Doro 的 Python、Qt 與單一角色，不加入另一套 Node gateway。

## 先完成可用的本機任務閉環

1. 獨立的 TaskDecision 與工具表：模型每次只能提出一個通過 schema 的工具呼叫，
   工具清單由程式提供；步數、連續錯誤與取消都有硬限制。原始使用者目標保留，
   工具結果、檔案、網頁及記憶不能成為新的授權。模型先提供短計畫，最後依結果回報。
2. SQLite 保存任務、計畫、逐步結果及使用者記憶。每次副作用前記錄 intent，之後記錄結果。
   重啟時未完成任務標為 interrupted；只有使用者指定接續才重新規劃，不自動重播上一步。
   紀錄可列出、查看及刪除；記憶只由明確的「記住」指令建立，也可列出與忘記。
3. 本機工具先支援 Doro 專用工作目錄內的列目錄、讀文字、寫文字；相對路徑、大小及
   symlink 都檢查。寫入先呈現完整變更，確認後再查原檔指紋，檔案已改就拒絕覆蓋。
4. 指令只能在 Docker 隔離容器執行：固定映像、無網路、唯讀根目錄、工作目錄掛載、
   資源限制、逾時及取消清理。每次顯示完整 argv 並確認。Docker 或映像未安裝時明確
   回報不可用，不退回主機 shell、不自動下載映像。這是可選能力，檔案任務不依賴 Docker。
5. 將讀頁、搜尋與既有網站操作接入工具表；網站操作仍需原開關及原確認。
   共用 WebRuntime 序列執行，Playwright 不跨執行緒。工具只回報實際觀察，不能將停止
   或登入牆當成完成。聊天入口可自然語言選 task，也提供直接任務／接續指令。
6. UI 提供任務助理開關、工作目錄及操作說明。任務初始預設關；停、確認、busy 與
   心跳互斥沿用現有管線。頁面回答、分頁陪伴與心跳不會啟動任務。

## 設計檢查

- 路徑根目錄不是 shell 隔離：指令必須真的進容器。專用工作目錄不掛载個人主目錄、
  憑證、Docker socket 或任務資料庫。工作目錄內的程式可修改其中的檔案，確認會說明此範圍。
- 使用者拒絕或確認逾時就停止整個任務，模型不能换工具重試同一個副作用。
- 確認後仍查取消與原檔；每步保存結果，取消不能撤銷已完成的副作用。
- 重啟後，pending intent 代表結果不確定，接續提示必須先觀察，不可盲目重播。
- 記憶與工具結果送到使用者設定的模型；UI 說明儲存位置及刪除方式，不默默記錄所有聊天。
- 長計畫不等於完成：驗收以實際檔案、執行結果、狀態與取消為準。

## 後續階段

完成共用任務核心後，再依序擴大：心跳 v2 的明確網站白名單與差異通知；具有效期和
明確範圍的排程授權；MCP 工具與憑證管理；Windows UIA 語意操作及真實桌面驗收。
這些不是本次先假裝可用的入口。任意主機指令、無人跨服務寫入及自由桌面座標操作不在此階段。

## 驗收

- 真實暫存工作目錄：逃逸／符號連結／二進位及大檔拒絕、確認期間檔案變更不覆蓋。
- 跨工具任務：讀檔→產生摘要→確認写入→讀回驗證；拒絕／取消／不合格模型回覆不執行。
- 持久狀態：重啟、接續、未完成 intent、逐步紀錄、刪除及記憶管理。
- 容器指令：成功、非零退出、逾時、取消、無 Docker／映像的錯誤與資源限制。
- Qt 接線：自然語言／直接命令入口、開關、busy 結束、頁面回答和 auto 回覆不能啟動任務。
- 完整現有測試、Chromium、本次新測試、Black、Ruff、repo map 及 diff 檢查後更新 PR。
