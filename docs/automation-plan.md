# Doro 自動操作擴充計畫

基準：`claude/sleepy-maxwell-ucte2w` 的 `0bd900cd67dfca5af791514253e2ea2d151eb04a`。
規劃日期：2026-10-12。先完成本計畫，再建立 `codex/comprehensive-web-automation`。

## 目標與現況

使用者希望 Doro 能更完整地自動操作。現有網站操作已能在 WebRuntime 專屬執行緒中
反覆觀察、決策、確認、執行，最多 12 步；普通讀頁、分頁陪伴與心跳的回覆仍不能啟動工具。
因此不以移除 `_auto_read_used` 或開放頁面回覆工具欄位達成多步操作。

目前實際缺口：新開的空白瀏覽器被 snapshot 當成錯誤；操作模型不能開新分頁或切換
分頁；select 雖被列出卻沒有對應動作；缺少明確勾選、懸停與短暫等待；DOM 編號可能
殘留、且模型等待或使用者確認期間目標可能變動；失敗只有步數上限，沒有連續失敗停止。

## 本分支範圍：完整一輪網站任務

範例：打開示範網站 → 選擇分類 → 勾選條件 → 等候載入 → 開啟另一分頁 → 切回原頁
→ 依結果完成或回報阻礙。所有操作繼續使用 Doro 自己的瀏覽器設定檔。

1. 延伸嚴格的 WebStep：`select(n, text)`（精確選項文字）、`check(n, checked)`、
   `hover(n)`、`wait(seconds)`（0–5 秒）、`new_tab(url)`、`switch_tab(tab_id)`。
   元件與分頁編號為非負整數；只接受 http(s) 網址；錯誤格式重問後仍不合格就停止。
   填入文字原樣保留，不把首尾空白意外刪掉。
2. snapshot 提供可用分頁的穩定 ID、目前分頁、label、選項、勾選/停用狀態；不提供
   輸入值或密碼。空白頁可作操作起點，唯讀路徑仍回報沒有內容。
   以當次快照的實際 DOM 身分綁定索引，移除殘留編號；觀察後換頁或目標被替換時拒絕操作。
3. 在原執行器加入動作；執行前檢查目標仍存在、類型合適、非敏感且可互動。
   分頁 ID 綁 Page 物件，關閉分頁不重用 ID；未知 ID 拒絕，連結另開分頁後能看見並切換。
4. 操作迴圈提供動作說明、當前步驟與短歷史，錯誤交回模型重新觀察；連續三次執行失敗
   停止。同一編號在不同頁面可以正常點擊；同頁同目標重複且無進展才警告。
5. 每個新增動作沿用取消檢查與既有確認路徑。select/check 的 change handler 可能
   立即送出，所以本版皆需確認；hover/切分頁/短等待本身免確認。送出類點擊/按鍵維持確認。
   確認期間目標替換、導航、敏感性或語義變動，已給的確認不套用到新目標。
6. 網頁、元件文字與工具結果明確視為不可信資料；不開放 shell、任意 JS、檔案操作、
   模型新增權限或讓心跳啟動網站/桌面操作。

## 後續階段與依賴

- 心跳 v2：遵循 TODO 已定案的 HTTP 白名單、首次基準、差異摘要及唯讀限制，獨立實作。
- 持久記憶：定義讀寫、刪除、保留期間、來源標記；任務中間狀態與個人長期記憶分開。
- 跨工具任務協調：明確的任務狀態、來源及授權，連接搜尋/讀頁/操作；先有工具能力表
  與結果格式，再擴大 planner。不能讓不可信頁面直接升級成桌面權限。
- Windows 桌面能力：沿用前景白名單、UIA、Esc 與 ActionDispatcher，先擴充語意輸入、
  選擇與結果觀察；需 Windows 真實 UI 驗收後才宣稱支援。
- 無人任務、MCP 與腳本：獨立 ADR、任務授權、隔離環境及稽核；本次不開啟。

## 驗收與回滾

- 修改前先跑 web/chat/llm 的既有測試，記錄基線。
- 單元測試涵蓋格式邊界、錯誤參數、確認拒絕、取消、步數及連續失敗上限。
- 真實 Chromium 只用隔離 profile 與本機假資料：空白頁起步、select/check、hover、
  等待動態內容、分頁開啟切換、關閉分頁 ID、DOM 替換與確認過期，不使用真帳號。
- 完整非手動測試、Black/Ruff 及 repo_map 一致性檢查；受環境阻擋項目明確記錄。
- 文件更新 README、功能說明、ADR、TODO、areas.json 與生成地圖；保留原始來源分支。
- 新分支可獨立審查及回退；本次不合併回來源分支。

已知邊界：網站自訂腳本副作用無法完全由 DOM 推論；已發出的單次動作無法用取消撤回。
假網站驗收證明操作流程與限制，不等於任意真實網站或模型都能正確完成任務。
