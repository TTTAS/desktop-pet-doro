# ADR 0002：事件驅動的情境活潑

- 狀態：採用
- 日期：2026-09-10

## 背景

現有 IdleBehaviorManager 已能走路、換狀態、說預寫台詞。情境理解不能取代這層，也不應對同一頁反覆呼叫模型。

## 決策

- 保留基本活潑的既有隨機節奏；情境活潑由新的分頁事件觸發。
- 正規化空白後的相同 URL／標題／內容雜湊先在本機去重；最近 256 份指紋只作記憶體快取，不是發言次數額度。
- 不同文字但相同意思由 LLM 比較上一則反應，回 `[SILENT]`；本機雜湊不被宣稱為完整語意判斷。
- 同時最多一個情境模型請求。忙碌時只保留最新頁面；不把中間每個變化排成長隊。
- 換頁、失去有效分享、停用或使用者開始發問後，舊模型結果不得發言。只是角色還在走路時，結果可以等到動作完成。
- 失敗只進入降級狀態，不立刻重試同一個事件、不停掉基本活潑；下一個新事件可以恢復。
- 不設定情境發言的時間冷卻、每日次數或總次數上限。250ms GUI 排隊檢查、傳輸重連與心跳均不是 LLM 呼叫排程。

## 結果與限制

頻繁变化不會累積過時請求，但穩定新內容仍能接續處理。
語意是否相同依賴使用者設定的模型，不能保證所有改寫都被去重。
現有明確網站操作的 12 步限制是另一條任務執行保護，不是存在感的發言上限。
